啊这个这个啊，是吧

也不知道更点啥，web题暂时懒得写，寻思靶场弄了这么久，打完一套拉倒吧，后面换bp的靶场玩玩

DVWA 一共包含了十个攻击模块，分别是：Brute Force（暴力破解）、Command Injection（命令行注入）、CSRF（跨站请求伪造）、File Inclusion（文件包含）、File Upload（文件上传）、Insecure CAPTCHA （不安全的验证码）、SQL Injection（SQL注入）、SQL Injection（Blind）（SQL盲注）、XSS（Reflected）（反射型跨站脚本）、XSS（Stored）（存储型跨站脚本）。包含了 OWASP TOP10 的所有攻击漏洞的练习环境，一站式解决所有 Web 渗透的学习环境

这个靶场是用php study搭好的，具体教程自己去网上找就好，好多呢

一、brute force

这个叫暴力破解，就是通过自动化工具，反复尝试各种账号密码直到‘撞’上了为止，也就是——穷举法

操作步骤大致就是：准备字典(各种账户，密码)，用工具(这里使用burp suite)，判断响应内容/长度/依赖码来确定有没有成功

这个方法是依赖于系统没做限制尝试次数，没有验证码或登录锁定机制的，有了就不好搞了

此举目的是获取管理员/普通用户的登录凭证，进而提权，然后做坏事○( ＾皿＾)っHiahiahia…

我们主要是为了理解弱密码危害，服务端防护手段(限流，验证码，锁号，二级密码等)，以及bp使用。low是单纯爆破即可，med是要学会观察sleep延迟，理解防爆破靠延迟没用，high则是要分析源代码，找到token，写脚本带token爆破

low

内容很简单，就是登陆框，瞎输点内容会提示账户密码错误，输对了也有提示，和一个图片(其实账密就是靶场默认的那个)，我们直接打开bp，内置浏览器登入靶场，拦截请求，发送到攻击器里，然后攻击类型选择第四种，在账号密码后加上载荷，分别设好载荷类型(指定文件)，在配置里选好字典

随后开始攻击，根据上面所说，直接去看状态码，响应，还有长度那里，发现有一个组合的长度明显不同，我们点击查看，在下面的响应框里选择页面渲染，发现提示登陆成功，所以这个账密是对的

通过观察源码，我们发现，输入框中字符串被直接拿去放到数据库里比对，那也就是说，我们也可以通过sql注入的方式，下面是源代码，我们直接在用户处输入admin ‘or’’=’，就可以闭合前半段代码，相当于是查询admin用户，中间的or表示后面的内容只要一个条件为真，那么整个条件为真，之后是‘’=‘’，一个永真的条件，最后是密码。

也就是说，这条命令被我们改为了查询admin用户的情况下，两个条件(前永真，后或真或假)只要对一个就算你通过，所以效果就是密码随便输一个都会显示正确。

而根据bp实测，在密码正确的情况下，反而会报错，这是因为dvwa的源代码中有这样一个规则，就是拿着用户名去比对，发现密码正确，即返回true，但经过我们的魔改，后面是一个true带一个true/false的，只有一个对，那系统返回一个true，默认密码正确，返回两个true，系统会认为用户匹配到了两个库中的密码，这是不正常的，系统判断不出你要用哪个身份登录，所以会报错

那么由此，我们可以得出另一个更好的方法，直接admin ' --空格 ，前面依旧负责闭合命令，直接用admin身份登录，后面的<–空格>负责把后面的密码匹配注释掉，根本不检查密码，那么我们就能直接登录了

(o゜▽゜)o☆[BINGO!]

med

先来分析源代码，med对用户名和密码做了查询，并且这段$user = mysqli_real_escape_string($conn, $user);代码，是对特殊字符做了转义，防止sql注入。后面的三个$pass则是获取密码，转义和加密。最后就是用sql语句去查询，判断对错。

其中后面的sleep(2)是做了登陆失败后两秒禁止操作，这会使攻击时间变得很长，不过我们依然可以采取爆破的方式，因为没有限制次数，没有验证码，且成功与否会有明确信息，多刷会视频就好

high

这是high的源码，很明显，这次多了检查TOKEN的环节，也就是CSRF token

CSRF是跨站请求伪造，token就是生成的一次性令牌，用来验证请求是用户提交而不是伪造的，登录表单会有一个字段，后面的值是一堆乱七八糟的字符串，每次刷新页面都会重新生成

增加token查验环节是为了防自动化爆破，脚本必须要现获取token，增加了攻击难度；

防CSRF攻击，恶意网站没法提前得到token，很难伪造登录请求；

会话绑定，token会储存在session中，提交时会校验

虽然CRSF增加了难度，但是我们只需要加一步获取token就行。

这里我尝试了如果密码对了但token不对，密码对token对，密码不对token对三种情况，但是很意外，如果我删改token值，爆破情况和med一样，没有token错误的提示，如果把token检验代码去掉，那么不论密码对与否，返回长度都是一样的，但是依然没有报错？？？他没有正常进行token校验啊

下面是网上搜到的方法：

默认用户是admin，在password和token处设置载荷，选择草叉攻击(两个字典要一一对应)，因为我们是要动态获取token值的，所以接下来要使用bp的一个叫grep extract的功能（他会从html页面里抠出一个特定文本，每次爆破时都会动态获取这个值）找到这个功能直接点进去，点击获取响应，找到我们要动态获取的token字段，然后霜鸡!!!上面会自动填值，之后点击确定即可

回到载荷设置，选择递归提取(拿到一次token就填充一次新的)然后开始攻击

下面是几种攻击的区别

Sniper： 单参数爆破，使用多个字典按顺序替换，只有一个数据会被替换，只针对一个值
Battering ram： 多参数同时爆破，但用的是同一个字典，每个参数数据都是一致的
Pichfork： 多参数同时爆破，但用的是不同的字典，不同字典间数据逐行匹配
Cluster bamb： 多参数做笛卡尔乘积模式爆破,就是啥也不知道，纯暴力撞

二、command injection

刚发现你玖叔叔给的这玩他也不全啊，命令行注入这一块的source文件夹没了啊，啥也没有要不提示我找不到文件夹呢，没关系，我们手动补全即可，去GitHub找源代码复制粘贴

命令行注入简单来说就是让程序执行你想执行的命令而不是他要执行的，因为有些代码会直接把用户输入的字符串拼进命令行，就是字符串拼接，没有做转义或者黑白名单这样，和sql注入差不多道理

使用的符号

；顺序执行，跑完你的跑你的，跑完你的跑…

&& 前面的成功了再执行后面的

& 后台执行，前面无论成功与否，后面都执行

|| 前面的失败了才执行后面的

| 前面无论执行与否，都会执行后面的命令且只会执行后面的一个

` 命令替换

这一块主要是要明白信任边界，用户输入默认全不可信，系统命令执行是高权限的，两者要有隔离，且黑名单不是万能的，黑名单永远可以被绕过，只要你比开发者更懂系统，而白名单是更可靠选择，比如你只允许用户输入什么内容，其余全部拒绝

low

先看源码，这个环境是让我们去ping一个ip地址，那么我们可以利用|和&来捎带上我们要执行的命令，源码里面没做什么过滤，但有一点，他是在CMD里面去跑的，所以注意用win的命令，比如127.0.0.1 && whoami查看当前用户

med

依旧先看源码，发现多了'&&' => '', ';' => '',这个东西，是把&&和；符给ban了，但是无伤大雅，因为还有别的可用127.0.0.1 |/& whoami这俩都行

high

源码依旧，发现他给这点玩意都ban了，但只要你细看，你会发现|后面居然有个空格，有个空格，那不和没ban一样吗，你写的时候不带空格不完了吗，或者你加tab缩进，用编码代替，换行也成

也就是127.0.0.1 |whoami,验证通过

主要是啥呢，high突出一个黑名单防不完的问题，你想不全所有的攻击方式，所以你只能赌，赌我想不到别的方法，于是乎推荐白名单，除了我让你输的其余全不合法，这个更靠谱。

三、csrf

跨站请求伪造，就是顶着你的身份干坏事，你还不知道。需要两个条件，一是用户已登录，浏览器缓存里有你的session/cookie，二是你要干的事情不需要额外的验证(基本只靠cookie就可以的那种)

我们主要是要明白csrf本质上是权限滥用，防御这种攻击依然还是推荐白名单，且每一步最好都要有身份验证

这个环境是让我们改新密码，然后通过一些手段让密码变成我们想要的

low

先来看源码，前几行是检查url参数的，看看你是不是要改密码，这里注意一点“获取参数他用的是GET，这意味着所有请求的参数都会出现在url栏里，也就是说我们可以看到，更改”。

继续向下看，两行是输入新密码，确认新密码做了一个判断，但是他从始至终没有验证旧密码，这就意味着，只要我知道这个页面，那我可以随时改你的密码。

$pass_new = md5( $pass_new );接下来这段是做了一个加密，随后两行是更新数据库的数据，$insert = "UPDATE users SET password = '$pass_new' WHERE user = '" . dvwaCurrentUser() . "';";这里直接就更新了，依然没有询问，不验token。最后是成功的消息

这个攻击关键在于url，通过bp抓包或者实际试一遍我们会得到[Vulnerability: Cross Site Request Forgery (CSRF) :: Damn Vulnerable Web Application (DVWA)](http://127.0.0.1:8898/vulnerabilities/csrf/?password_new=password&password_conf=password&Change=Change#)这么一个东西，有了这个，我们可以抓取并且改掉一些东西，比如说改成我们想要的密码，把这个url伪装成别的东西，诱导点击，可以是一封邮件，一个图片，一个链接都行，甚至我可以直接来一个只要你的浏览器渲染到了就会执行，压根不需要有人点击

之前我在攻击人生online.cc网站时的任务标签xss漏洞利用就用到了这个，插入了一段只要渲染到就跳转B站的代码，然后结果就是一访问网站就跳转，因为这个已经储存到数据库了，最后让人家从后台删掉的

med

还是看源码，发现他新增了两条

这个是referer检查，先是检查了请求来源页面(从哪个页面跳转来的)，然后是服务器域名(如果包含合法域名会继续下一步，不合法返回false)，其他地方和low一样

这个就是referer检查那一段的信息

stripos()检查的只是包不包含域名，而不是完整路径是否合法，也就是说只要请求里带有域名，就能通过检查。比如说，这里的域名应该是127.0.0.1，那我自行构造一个127.0.0.1.IKUN.com的域名也可以，因为里面包含了127.0.0.1

或者还有一个方法，路径欺骗，因为他不检查路径是否合法，所以我们在合法url里面加一个服务器上可能不存在的地址上去也行

referer只做字符串匹配

所以攻击方式就是通过拦截改掉信息，可以改域名也可以改路径，两个都改也行

还有另一个办法，但算是文件上传漏洞，就是如果你可以往服务器里上传文件的话，上传一个html文件，里面写上<img src="恶意改密码的url"/>之后诱导点击即可

high

源代码多出两个部分，就是最重要的验证token部分，第一大部分是在判断你的请求类型，html还是json，json的token放在请求头，html还在body里，token是一次性的。这次改换了post请求，

GET会把信息都放在url里面，直接明文传输，最危险，POST会把密码放在body里面，url也不会显示其他信息。大厂的做法是POST发送，用HTTPS加密传输，以及MD5加密密码，这样能最大限度保证密码不被泄露，最好在操作时还有验证token，输入验证码或旧密码这一步

代码分析差不多，开始构思攻击。

第一种利用XSS，如果页面存在XSS漏洞，那可以尝试读取页面的token，再利用token发起改密码的请求

不过我发现个问题，我拦截拿到的token，然后放行，刷新页面，再次拦截，发现token改变，更换为我拿到的本应失效的token，再点发送，居然可以正常改密码？？？意思是他压根也没排查我的token？？

第二种中间人攻击，如果网站不强制HTTPS，那我们可以劫持流量，直接拿走token

第三种是点击劫持，构造一个界面诱导用户点击，然后读取token，把密码接到改密码的表单上，再让用户点击，但这个实在太麻烦了，我搞不来……

token机制可以防外部的csrf，但防不住站内的同源csrf
